Step 1

Plan what you're building

Before you open Claude, get clear on three things — it makes the result far better:

  • Purpose: portfolio, landing page, blog, resume, product page, documentation?
  • Content: gather your text, images, links and any copy you already have.
  • Look & feel: colors, fonts, and 2–3 sites you like the style of (send Claude links or screenshots).
Tip: GitHub Pages serves static files only — HTML, CSS, JS, images. No PHP, no databases, no server-side code. Perfect for portfolios, docs, landing pages, and most small business sites.
Step 2

Build the page with Claude

Open claude.ai (or Claude Code in your terminal) and describe your site. Be specific — Claude responds best to detail.

Example prompt:

I want a single-page personal portfolio website.
Sections: Hero with my name and title, About, Projects
(3 cards), Contact with email + social links.
Style: dark background, one accent color (teal),
clean sans-serif, generous whitespace, mobile responsive.
Output: a single index.html with inline CSS, no
frameworks or build tools — it must run by just
opening the file, and later by GitHub Pages.

Iterate conversationally: ask for tweaks ("make the hero bigger", "swap the accent to purple", "add a dark/light toggle"). When happy, ask Claude for the final, complete file — not snippets.

Keep it static. Ask Claude to avoid Node.js servers, databases, or `.env` secrets. Everything needs to work as plain files opened in a browser / served statically.

A minimal structure to request

my-website/
├── index.html
├── style.css
├── script.js
└── images/
    └── (your assets)
Step 3

Create a GitHub repository

  1. Go to github.com/new.
  2. Name it something like my-website (or yourusername.github.io — see the box below).
  3. Set it to Public (required for free GitHub Pages).
  4. Click Create repository.
Naming matters: a repo literally named yourusername.github.io is published at the root domain https://yourusername.github.io. Any other repo name, e.g. my-website, is published at https://yourusername.github.io/my-website/. If you plan to use a custom domain anyway, either naming works fine.

Push your files from the terminal

cd my-website
git init
git add .
git commit -m "Initial site"
git branch -M main
git remote add origin git@github.com:yourusername/my-website.git
git push -u origin main

No terminal? Drag your files straight into the repo page in the browser via Add file → Upload files, then commit.

Step 4

Turn on GitHub Pages

  1. In your repo, go to Settings → Pages.
  2. Under Build and deployment, set Source to Deploy from a branch.
  3. Choose branch main and folder / (root), then Save.
  4. Wait ~1 minute. GitHub shows a green banner with your live URL: https://yourusername.github.io/my-website/
Every push redeploys automatically. Edit your files, commit, push — Pages rebuilds in under a minute. No manual redeploy step needed.
Step 5

Point your custom domain at it

You'll need a domain you own (e.g. bought via Namecheap, Cloudflare, GoDaddy, or Domeneshop).

A. Add a CNAME file to your repo

echo "www.yourdomain.com" > CNAME
git add CNAME
git commit -m "Add custom domain"
git push

Or just type your domain into Settings → Pages → Custom domain — GitHub creates the file for you.

B. Set your DNS records

At your domain registrar's DNS settings, choose one of these setups:

Use caseTypeHostValue
Root domain
yourdomain.com		A@185.199.108.153
A@185.199.109.153
A@185.199.110.153
A@185.199.111.153
www subdomain
www.yourdomain.com		CNAMEwwwyourusername.github.io
Recommended: use the 4 A records for the apex/root domain and the CNAME record for www. Then set either as your "preferred" domain in GitHub Pages settings — GitHub redirects the other one to it automatically.

C. Verify in GitHub

  1. Go back to Settings → Pages.
  2. Enter your custom domain and save — GitHub starts a DNS check (can take a few minutes to 24h).
  3. Once verified, tick Enforce HTTPS for a free, auto-renewed SSL certificate.
DNS propagation: changes can take anywhere from a few minutes to 24–48 hours to take full effect worldwide. If HTTPS enforcement is greyed out, wait and check back later.
FAQ

Good to know

Is this really free?

Yes — GitHub Pages hosting is free for public repositories, including HTTPS. You only pay for the domain name itself if you want one.

Can I use a framework like React?

Yes, as long as the final build output is static files. Ask Claude to set up a build step (e.g. Vite) and publish the compiled dist/ folder, or use a GitHub Action to build automatically on push.

Can I keep editing with Claude later?

Absolutely. Paste your current HTML/CSS back to Claude, describe the change, get the updated file, commit, push — live again in under a minute.

What if my site doesn't show up?

Check: repo is public, Pages source points to the right branch/folder, and there's an index.html at the root (or the folder you selected). Hard-refresh your browser — Pages can cache briefly.
